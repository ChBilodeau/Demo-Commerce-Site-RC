# Phase 3 — Coveo setup

Goal: get the product catalog into the user's Coveo org and routed to the
commerce storefront. Mix of automated (source/fields/push) and guided
(catalog config + storefront association, which are console-only).

Prereqs: the user's Coveo **organization id** (in `demo.config.json`) and a
**privileged setup API key** (source push + field edit). Pass the key as an env
var to scripts — never write it to `demo.config.json`.

## 3a. Create the commerce push source (automated)

1. Confirm with the user, then create a Catalog/Push source. Run
   `scripts/coveo-create-source.mjs`, which reads these env vars:
   - `COVEO_ORG_ID`, `COVEO_REGION`, `COVEO_SETUP_KEY`, `COVEO_SOURCE_NAME`.
   It prints the new **source id**. Save it into `demo.config.json`
   (`coveo.commerce.sourceId`) yourself.
2. If the user prefers, this can also be done in the Admin Console
   (Content → Sources → Add → Catalog). Either way, capture the source id.

## 3b. Create and map fields (automated)

The catalog uses the standard commerce fields (`ec_*`) plus a few extras. Use
the existing field/mapping scripts under `scripts/` (adapted from the working
site) — confirm, then run them with the org id + setup key as env vars. Verify
in the Admin Console (Content → Fields) that the fields exist.

## 3c. Push the catalog (automated)

1. The catalog JSON is generated by the Python generators under `scripts/`
   (products + self-variants). Generate it if not present.
2. Push it with `scripts/push-and-prune.py` (env: `COVEO_ORG_ID`,
   `COVEO_SOURCE_ID`, `COVEO_PUSH_KEY`). Confirm first — this writes to the
   source.
3. Verify: run `scripts/verify-coveo.mjs` (env: org id + access token + tracking
   id) and confirm the Commerce API returns products.

## 3d. Catalog config + storefront association (GUIDED — console only)

The Commerce API selects the pipeline + catalog server-side via the storefront
association tied to the tracking id. This can't be done with the push key; guide
the user:

1. Admin Console → Commerce → Catalogs: create a catalog config pointing at the
   source, with the product/variant id fields.
2. Admin Console → Commerce → Storefront associations: create an association for
   the user's **tracking id** (`demo.config.json` → `coveo.commerce.trackingId`)
   with the matching **locale** and pointing at the catalog + a query pipeline.
3. Capture the resulting catalog id into `demo.config.json`
   (`coveo.commerce.catalogId`) if the UI surfaces it.
4. Verify again with `scripts/verify-coveo.mjs` — the Commerce API should now
   return the catalog's products for the tracking id.

## Common pitfall

If the Commerce API returns `412 NO_CATALOG_MATCHES_REQUEST`, the locale in
`demo.config.json` doesn't match the storefront association's locale, or the
association/catalog isn't set up yet. Fix the locale or the association.

## Done when

`scripts/verify-coveo.mjs` returns products for the tracking id.

Continue to `references/04-salesforce.md` (only if Support is enabled; otherwise
skip to `references/05-features.md`).
